# Разработка Lanka

Работайте в отдельной ветке. Сохраняйте чужие изменения и пользовательские данные; тесты должны создавать собственные документы, tenants и временные каталоги. Исходный код Lanka распространяется под Apache 2.0; см. LICENSE. Сохраняйте лицензии сторонних компонентов.

## Подготовка

Используйте Node.js ≥22.13 и lockfile репозитория:

```sh
npm ci
npm run build:mcp
```

Для редактора без чата достаточно файлового режима из [README](README.md). Используйте абсолютный физический путь (pwd -P): библиотека отклоняет пути через symlink. PostgreSQL-тесты требуют отдельной настройки по [LOCAL_CHAT_SETUP](docs/LOCAL_CHAT_SETUP.md); они читают приватный work/agent-chat/config.json. Не создавайте фиктивные credentials и не направляйте проверки в производственную базу.

## Карта кода

- lib/domain — DeckDoc, шаблоны, сцена, типографика, операции и правила проверки.
- components/project-workbench.tsx и editable-slide-canvas.tsx — текущий локальный/корпоративный редактор.
- lib/project — контракт документа, черновики, история, экспортные артефакты и файловые интерфейсы.
- lib/adapters/postgres — организации, права, документы, переписка и исполнение.
- scripts/project-mcp — локальные HTTP/stdio точки входа и сборка; lib/server/corporate-mcp.ts — корпоративный MCP.
- runtime — адаптер установленного агента и companion. Не подменяйте реальный ответ модели фикстурой.
- lib/export.ts — PDF/PPTX, использующие общую сцену; design-packs и public/fonts — дизайн и шрифты.
- deploy/self-hosted — Compose, роли БД и эксплуатация. db/self-hosted — миграции этого режима.
- app и часть lib/server — также содержат ранний Vinext/Cloudflare режим. Его D1-схема и доверенные заголовки не заменяют PostgreSQL/OIDC режим.

## Проверки по области изменения

Быстрая общая проверка без PostgreSQL и аккаунта агента:

```sh
npm run check:source
```

Она последовательно выполняет TypeScript, сборку MCP/редактора и тесты объектов, экспорта, протокола входа и все runtime/*.test.mjs (companion, отмена, восстановление, панель и transport). Набор runtime также запускается отдельно командой npm test --prefix runtime; тестовые CLI-пути не зависят от текущего каталога. Первый сбой останавливает выполнение; каждый шаг ограничен тремя минутами. GitHub Actions в .github/workflows/check.yml запускает эту команду для pull request и по workflow_dispatch, затем собирает self-hosted образ и запускает изолированный Compose-сценарий с тестовым OIDC, экспортом, восстановлением и проверкой доступа. Workflow не публикует образ и не использует production-секреты. Реальные браузерные, PostgreSQL, агентные и Office-проверки остаются отдельными.

Браузерная проверка редактора из корня:

```sh
npx playwright install --only-shell chromium
npm run check:editor-browser
npm run check:editor-browser -- --lost-upload-response
```

Требуется Chromium для установленной версии Playwright и его системные зависимости. Команда пересобирает редактор, запускает отдельный файловый сервер на свободном loopback-порту и создаёт временный документ. Проверяет выравнивание, автосохранение, Undo/Redo, перезагрузку и мобильную панель, прямой ввод/отмену текста, загрузку PNG и сохранение режима изображения. Сохраняет desktop/mobile PNG и result.json в новый out/editor-browser-*; результат записывается после завершения тестового сервера и удаления workspace. Она не подключается к вашей рабочей библиотеке, не использует аккаунт агента и не заменяет проверку PostgreSQL, реальной модели или ручную touch-приёмку. Режим --lost-upload-response намеренно обрывает первое подтверждение загрузки после ответа сервера и требует сохранения того же requestId при повторе из UI после reload. Перед повтором тест изменяет режим изображения и требует новую revision. Оба сценария добавлены отдельной matrix-задачей editor-browser в GitHub workflow с установкой Chromium и системных зависимостей. Конфигурация проверена локально; запуск GitHub ещё не выполнен.

Базовые команды из корня:

```sh
npx tsc --noEmit
npm run build:mcp
npm run build
```

Для объектов редактора без PostgreSQL:

```sh
node --test scripts/project-mcp/canvas-layer.test.mjs scripts/project-mcp/canvas-duplicate.test.mjs scripts/project-mcp/canvas-pagination.test.mjs
```

Для сохранённых экспортов и корпоративных прав после подготовки тестовой БД:

```sh
npm run test:export-artifacts
npm run test:resources
```

Для полного контейнерного сценария после сборки образа:

```sh
docker build -t lanka-self-hosted:local -f deploy/self-hosted/Dockerfile .
node scripts/check-self-hosted-compose.mjs
```

Последняя проверка создаёт свой Compose-проект, тестовый HTTPS IdP и тома, экспортирует документы, восстанавливает дамп в новые тома и удаляет собственные ресурсы. Она не проверяет реальную корпоративную авторизацию или модель. Нужны Docker Compose и openssl. Не запускайте её параллельно с пересборкой того же image tag.

npm run dev и npm run start относятся к Vinext/Cloudflare. npm run install:ci — специфический Linux/Sites wrapper, не универсальная замена npm ci на Mac. npm test не является полным набором проверок локального/корпоративного продукта.

## Изменения и приёмка

Сохраняйте стабильные IDs и revision, авторство, scoped permissions и идемпотентность. Новые MCP-операции должны описывать контекст, ограничения, повторы и требуемые права; проверяйте отказ после отзыва ключа. Агентное предложение не должно автоматически становиться принятым изменением.

UI-правку проверяйте в браузере на изолированной фикстуре: действие, сохранение, повторное открытие и подходящая мобильная ширина. Для экспорта проверяйте фактический файл; структура OOXML не заменяет просмотр и правку в PowerPoint. Не заявляйте визуальную или пользовательскую приёмку по одним тестам.

В описании изменения укажите проблему, новое поведение, выполненные проверки и оставшиеся ограничения. Не публикуйте токены, auth-файлы, дампы, переписку и частные материалы. work/, out/ и локальные runtime-каталоги не являются исходной поставкой. Обновляйте инструкции при изменении команд и сохраняйте доказательства в docs/planning без персональных данных.

## Список npm-зависимостей для поставки

```sh
mkdir -p out
npm run package:sbom -- out/release-sbom
```

Укажите новый каталог: существующий не перезаписывается. Получаются sbom.cdx.json (CycloneDX из lockfile, включая dev/optional) и manifest.json с хешами package.json, package-lock.json и SBOM. Повторные npm package identities нормализуются с сохранением всех путей и объединением связей; конфликтующие идентичности или хеши отклоняются. Это список npm-состава, а не inventory установленного контейнера: OS-пакеты, внешний PostgreSQL/Codex и шрифты учитываются отдельно. Он не выбирает лицензию Lanka. Генератор проверяет структуру и целостность ссылок. Созданный 9 сентября пакет дополнительно прошёл официальную схему CycloneDX 1.5: доказательство (внутренний протокол разработки). Международные URI/email проверялись консервативным ASCII-подмножеством; все значения этого пакета прошли. Теперь каждый пакет перед записью автоматически проходит локальные официальные схемы из vendor/cyclonedx-1.5; загрузка схем из сети не требуется. Неподдерживаемая версия и невалидные данные останавливают генерацию. Международные URI/email вне ASCII пока отклоняются консервативно. Проверка генератора (внутренний протокол разработки).
