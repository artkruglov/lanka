# Локальный companion одной беседы Lanka

Это foreground runner для явно привязанной корпоративной MCP-беседы. Self-hosted сервер должен включать миграцию 0028. Нужны Node ≥22.13, установленный pinned Codex runtime и явный вход в отдельный профиль. Он не копирует вход настольного Codex. Лимит Lanka 20 запусков/UTC-сутки проверяет сервер при claim, совместно с локальным чатом.

## Отдельный комплект без клона приложения

Администратор может собрать локальный комплект из проверенного checkout:

```bash
npm run package:companion -- /absolute/new-output-directory
```

Команда создаёт папку `lanka-companion` и ZIP с исходниками мастера, панели и runner, закреплённым runtime/package-lock.json, инструкцией и SHA-256 manifest. Существующий выходной каталог не перезаписывается. Ключи, профили, документы, Node и бинарный Codex в архив не входят. Сотрудник распаковывает комплект и следует README; при уже установленном совместимом Codex npm-зависимости панели не нужны. Для установки Codex в комплект выполните `node runtime/companion-install.mjs` с утверждённым компанией npm registry. Команда запускает npm ci с optional dependencies и увеличенным сетевым тайм-аутом, затем проверяет именно бинарник комплекта; системная установка его не заменяет. Отдельно повторить проверку можно через `node runtime/companion-install-check.mjs`. Если npm сообщает `ECONNRESET`, загрузка оборвалась: проверьте доступ к утверждённому компанией registry и повторите установку после восстановления соединения. Успех npm без этой проверки недостаточен: optional-пакет может не установиться. Установка на чистой машине ещё требует отдельной приёмки.

Сборка не публикует архив и не выбирает лицензию продукта. Лицензия открытого выпуска остаётся решением владельца.

В распакованном комплекте доступны также npm-команды (из папки `lanka-companion`):

```bash
npm run install:runtime --prefix runtime
npm run check --prefix runtime
npm run setup --prefix runtime
npm run panel --prefix runtime -- --config /absolute/private/companion.json
```

`check` проверяет только установку закреплённого бинарника. Вход, доступ к беседе и модель проверяются кнопкой «Проверить подключение» в панели. Для администратора доступны `start`, `inspect` и `recover` с тем же аргументом `--config`. `recover` освобождает блокировки только после проверки условий восстановления; исполнителя затем нужно запускать явно. Эти npm-команды принадлежат автономному комплекту; в checkout приложения используйте прямые команды `node runtime/companion-….mjs`, приведённые ниже.

## Настройка без ручного JSON

В беседе выберите «Подключить агента», выдайте и привяжите ключ, затем нажмите «Скачать подключение к беседе». Из корня локального репозитория запустите:

```bash
node runtime/companion-setup.mjs
```

Мастер спросит путь к скачанному файлу, новый каталог настройки и модель. Он предложит установленный Codex только при совпадении с закреплённой версией runtime/package.json. По умолчанию внутри нового каталога создаются приватные profile и workspace; вход в новый профиль выполняется из панели. В расширенных настройках можно выбрать другой executable, существующий отдельный профиль и рабочий каталог. Если совместимый Codex не найден, мастер попросит его путь и не станет устанавливать runtime автоматически. Все пути должны быть абсолютными. Мастер принимает обычный скачанный файл, копирует подключение в каталог с правами 700 и сохраняет файлы с правами 600; оригинал в Downloads не меняет. Удалите исходный скачанный ключ после переноса, когда он больше не нужен. Существующий каталог не перезаписывается.

На выходе — готовые команды проверки подключения и запуска. Мастер не выполняет вход, не связывается с моделью и не устанавливает фоновую службу. Пока companion работает, держите терминал открытым; останавливайте его через Ctrl+C. Если пути к установленному runtime неизвестны, их нужно уточнить у администратора локальной установки. Полный запуск из интерфейса ещё разрабатывается.

## Панель управления в браузере

Мастер также выводит команду панели. Для существующей конфигурации:

```bash
node runtime/companion-panel.mjs --config /absolute/private/companion.json
```

Откройте напечатанную локальную ссылку. Панель показывает сервер Lanka и выбранную модель; после проверки доступа — название беседы из Lanka. Её идентификатор можно раскрыть отдельно. Название может быть получено даже при ещё не выполненном входе в native-профиль: это не подтверждение готовности модели. В панели доступны «Войти в Codex», «Проверить подключение», «Запустить» и «Остановить». Запуск разрешает обработку ожидающих и новых поручений выбранной беседы. Пока выполняется проверка или работает исполнитель, второй запуск недоступен. Остановка сначала показывает ожидание; при неопределённом исходе панель просит проверить состояние, а не объявляет успех.

Ссылка содержит временный доступ к управлению этим процессом; не пересылайте её. Она работает только на этом компьютере и перестаёт действовать после завершения панели. Панель не принимает новые пути, команды или профили через HTTP. Чтобы сменить конфигурацию, остановите процесс в терминале и запустите панель с нужным --config. Закрытие вкладки не останавливает исполнителя; используйте «Остановить» либо Ctrl+C в терминале. Запуск панели не выполняет вход в Codex и не запускает модель автоматически.

Это отдельная локальная панель: запуск из облачного редактора одним нажатием, автоматическая установка и pairing ещё не завершены.

## Ручная конфигурация

В интерфейсе создайте беседу и подключение с ограничением поручениями (taskBound). Сохраните выданный ключ в приватном JSON-файле (права 600, каталог 700); файл не должен находиться в Git. Поля:

| Поле | Значение |
| --- | --- |
| url | Точный HTTPS endpoint `/mcp/organizations/<tenant UUID>`; HTTP разрешён только на loopback |
| token | Выданный этой беседе MCP bearer |
| sessionId | ID беседы Lanka |
| stateDir | Абсолютный физический путь отдельного приватного каталога состояния |
| command | Абсолютный путь pinned executable Codex |
| codexHome | Абсолютный путь явно авторизованного отдельного профиля |
| cwd | Абсолютный рабочий каталог runner |
| model | Явно выбранная доступная модель |

Из корня репозитория:

```bash
node runtime/companion-daemon.mjs --config /absolute/private/companion.json
```

Процесс проверит соединение и вход до получения сообщений. Stdout показывает connected/working/answered и ID поручения; текст документов, bearer и ответы модели не выводятся в лог. Ctrl+C запрашивает остановку текущего хода. Файлы checkpoint содержат приватные ответы; храните их внутри корпоративного контура.

После ошибки или аварии не удаляйте lock и не запускайте ход заново вслепую. Checkpoint и состояние server/native процесса должны быть сопоставлены: автоматическое reconciliation ещё разрабатывается. Отдельная UI-кнопка запуска, unattended перезапуск и сквозная пользовательская приёмка пока не завершены. Продолжение native thread реализовано с проверкой завершения предыдущего хода; условия описаны ниже. Тестовый прогон с синтетическим native adapter не является проверкой модели.

При штатном повторном запуске процесс сверяет незавершённые checkpoints с журналом Lanka: если точный ответ уже сохранён и исполнитель сообщил завершение, локальный статус восстанавливается без повторной модели. Подтверждённая отмена с terminal report также восстанавливается. Живое или неопределённое исполнение и stale locks автоматически не перехватываются.

## Подключение, скачанное из беседы

В окне «Подключение к беседе» после успешной выдачи и привязки ключа доступно «Скачать подключение к беседе». Файл `lanka-conversation-<sessionId>.json` уже содержит endpoint, ID беседы и ключ. Он не является настройками MCP для произвольного клиента: для них сохранена отдельная кнопка «Скачать настройки MCP».

Перенесите файл в приватный каталог и установите права 600. В локальном JSON runner вместо url/token/sessionId можно указать абсолютный `connectionPath` к этому файлу; stateDir, command, codexHome, cwd и model остаются вашими локальными настройками. Нельзя одновременно задать connectionPath и url/token/sessionId — неоднозначная конфигурация отклоняется. Команды и профили из скачанного файла не принимаются. Затем используйте ту же команду запуска выше.

Скачивание само по себе не запускает процесс и не выполняет вход. Неудавшаяся привязка ключа не показывает кнопку экспорта для беседы. Файл всё ещё является секретом с ограниченным сроком доступа; окончательную проверку срока и отзыва выполняет сервер.

Если отказ случился до регистрации исполнения и до отправки native turn, повторный запуск сверит отсутствие execution на сервере и сможет повторить claim с тем же ID. Это также работает после обновления дневной квоты; сам лимит не сбрасывается. Уже зарегистрированный или неопределённый native запуск автоматически не повторяется.

После успешного ответа runner сохраняет native thread/turn и продолжает ту же сессию при следующем сообщении. Перед resume он проверяет завершение последнего хода и заново применяет MCP scope. Несовпадение последнего хода блокирует продолжение; смена выбранной модели создаёт свежий native-контекст с историей Lanka. Реальная многоклиентная приёмка этой функции ещё открыта.

## Проверка до запуска

```bash
node runtime/companion-daemon.mjs --check --config /absolute/private/companion.json
```

Команда читает привязку ключа к беседе, проверяет вход в выбранный отдельный профиль и наличие точного имени модели в каталоге Codex. Она не получает поручение, не делает claim и не запускает модель. `connection_checked` подтверждает эти предварительные проверки; успешный inference, выполнение MCP-инструментов и качество результата требуют отдельного сквозного прогона. При старте daemon та же проверка выполняется до получения первого поручения. Изменение доступности модели позже всё ещё может привести к ошибке выполнения.

При отказе stderr содержит JSON `needs_attention` с кодом и следующим шагом: `AUTH_REQUIRED` — войти в отдельный профиль; `BINDING_REQUIRED` — привязать ключ к беседе с ограничением поручениями; `ACCESS_DENIED` — проверить ключ; `CONFIGURATION` — локальные настройки и права; `INSTANCE_LOCKED` — проверить прежний процесс. `NETWORK_UNCERTAIN` не означает, что отправленная операция не сохранилась. `INTERRUPTED` означает запрос остановки, а не подтверждённое завершение native turn. Неопознанные ошибки дают `UNKNOWN`; исходные тексты ошибок, пути и секреты в диагностический вывод не попадают.

Если ответ и terminal checkpoint сохранены, но процесс завершился до обновления native-session.json, при следующем запуске companion восстанавливает указатель по заранее записанному native-session-pending.json. Он проверяет совпадение беседы, поручения и execution, наличие сохранённого ответа и native IDs. Модель берётся из записи исходного запуска; смена настройки модели по-прежнему начинает новый контекст. Сообщение `session_recovered` означает восстановление локального указателя, а не новый ответ модели. Stale locks после жёсткого завершения процесса автоматически не удаляются; неизвестное исполнение не повторяется.

## Вход в Codex из панели

Нажмите «Войти в Codex», откройте предложенную страницу OpenAI и введите показанный код. Вход сохраняет сам Codex в профиле, выбранном при настройке companion. Панель не копирует авторизацию настольного приложения и не запрашивает пароль в Lanka. Если в выбранном профиле уже есть аккаунт, новый вход не создаётся и аккаунт не заменяется.

Во время входа запуск и проверка заблокированы. «Отменить вход» отменяет текущую попытку; через 10 минут локальное ожидание также завершается. Код исчезает после завершения, ошибки или отмены. Успешное уведомление сверяется с account/read. Затем выполните «Проверить подключение» и «Запустить». Успешный вход сам по себе не запускает модель и не проверяет доступность выбранной модели.

Механизм основан на [device-code flow Codex App Server](https://learn.chatgpt.com/docs/app-server). Реальная авторизация пользователя и модельный сценарий ещё требуют сквозной приёмки.

## Открытие панели из беседы Lanka

В настройках подключения беседы раскройте «Локальная панель агента», вставьте ссылку из терминала панели и сохраните её. После этого «Открыть панель агента» открывает управление в отдельной вкладке. Ссылка хранится в sessionStorage текущего браузера с областью пользователя/организации/беседы, серверу Lanka не отправляется.

Принимается только HTTP-ссылка на 127.0.0.1 с портом и capability после #. Lanka добавляет идентификатор текущей беседы и полный адрес MCP текущей организации; если конфигурация панели им не соответствует, панель показывает отказ вместо управления. Это также различает рабочую и тестовую установки с одинаковыми ID. Старую сохранённую ссылку редактор дополняет текущим endpoint при загрузке; ранее скопированную ссылку только с sessionId нужно открыть заново из редактора. После перезапуска процесса панели замените ссылку на новую. Это переход к уже запущенной панели, не установка и не автоматический запуск процесса. Перед запуском также сверьте сервер и модель, показанные панелью.

Если модель не найдена в каталоге, панель сообщает MODEL_UNAVAILABLE. Автоматического выбора другой модели нет. Проверьте имя в companion.json и доступ выбранного аккаунта; после изменения конфигурации перезапустите процесс панели. Скрытые модели учитываются при точном явном выборе. Неполный или ошибочный каталог считается ошибкой протокола, а не доказательством отсутствия модели.

### Выбор модели в панели

После входа нажмите «Выбрать модель»: панель прочитает каталог выбранного Codex без запуска модели. Выберите модель, проверьте подключение и нажмите «Запустить». Этот выбор действует для запуска из текущей страницы; сохранённая конфигурация не переписывается. После перезагрузки страницы при необходимости выберите модель заново. Во время работы переключение недоступно. Отсутствующая модель не заменяется автоматически моделью по умолчанию.

### Отмена предварительной проверки

Во время чтения каталога или проверки подключения кнопка называется «Отменить проверку». Она прерывает чтение и не запускает модель. Native-проверка имеет общий предел в 60 секунд; после отмены или тайм-аута её можно повторить. Остановка уже работающего агента отдельно требует подтверждения исполнения и не считается завершённой только по нажатию кнопки.

## Диагностика блокировок после сбоя

```bash
node runtime/companion-inspect.mjs --config /absolute/private/companion.json
```

Команда читает только локальные блокировки и наличие процессов. `process_exists` — PID существует, но мог быть использован повторно; `process_absent` — такого PID сейчас нет. Ни один из этих результатов не подтверждает остановку native-модели. `unknown` — сведений недостаточно (в том числе старый пустой lock); `another_host` — другой хост. Ответ явно содержит `nativeExecution: not_checked`. Секрет подключения и текст checkpoint не выводятся. Команда ничего не удаляет, не выполняет MCP-записи и не запускает модель. Новые блокировки содержат PID, хост, время и случайный идентификатор владельца. Автоматическое снятие блокировки после аварии остаётся незавершённым: сначала требуется сопоставить состояние native/server исполнения.

Для чтения серверного журнала добавьте `--server`:

```bash
node runtime/companion-inspect.mjs --config /absolute/private/companion.json --server
```

Нужен действующий ключ беседы. `reconciled` означает точное совпадение сохранённого ответа/карточек либо отмену вместе с terminal report внешнего исполнителя; `ready_to_claim` — сервер не зарегистрировал исполнение и локальный журнал подтверждает отсутствие native startup. `unconfirmed` означает недостаток подтверждений, `checkpoint_changed` — локальное состояние изменилось за время чтения. Отчёт проверяет не более 20 checkpoint и явно помечает `truncated`, если их больше. Он не изменяет checkpoint, не снимает lock и не является разрешением запуска: состояние native процесса непосредственно не проверялось (`server_report_only`).

Чтобы дополнительно прочитать конкретные сохранённые native thread/turn, используйте `--server --native`. Команда открывает выбранный Codex с изолированным sqlite_home, не выполняет вход, resume или turn/start. `terminal_snapshot` означает, что точный последний ход и все ходы этой сессии в момент чтения были terminal; это не межпроцессная блокировка. `missing_identity` — в checkpoint нет обоих идентификаторов, `unconfirmed` — подтверждение не получено. Если checkpoint изменился за время сверки, native-подтверждение сбрасывается. По этому отчёту нельзя автоматически удалять lock: защита от параллельного запуска и итоговая процедура восстановления ещё требуют реализации.

## Освобождение подтверждённых блокировок

```bash
node runtime/companion-reclaim.mjs --config /absolute/private/companion.json
```

Команда выполняет восстановление блокировок, но не запускает исполнителя. Требуются совпадающая область подключения, новые блокировки с подтверждённо отсутствующими локальными PID, проверенные checkpoints и доступ к Lanka. Для завершённого исполнения нужны точные server-подтверждения и terminal native snapshot. Для ошибки до native startup нужно серверное подтверждение отсутствия зарегистрированного исполнения. Неопределённые случаи отклоняются.

Все проверки выполняются до снятия блокировок; глобальная блокировка снимается последней. Checkpoints не переписываются: обычный запуск использует существующую reconciliation. Перед удалением повторно проверяются состав каталога, содержимое файлов и владельцы. Параллельные восстановления исключаются через recovery.lock. После успеха запустите обычную проверку и исполнителя из панели.

Ограничения: старые пустые lock, другой хост, живой/неизвестный PID, неполные server/native сведения и более 100 checkpoints требуют отдельного разбора. Сбой самой recovery-процедуры с SIGKILL может оставить recovery.lock; её автоматическое повторное восстановление ещё не реализовано. Read snapshots не дают межпроцессной блокировки произвольных внешних клиентов native-профиля — используйте отдельный профиль Lanka. Реальная модельная приёмка аварийного восстановления остаётся открытой.

В панели после ошибки занятого состояния появляется «Проверить и восстановить». Кнопка выполняет ту же процедуру reclaim с текущей локальной конфигурацией. Пока идёт проверка, другие операции недоступны. Успех не запускает агента: затем выполните обычную проверку подключения и запуск. При недостатке подтверждений панель показывает отказ; запрос отмены не выдаётся за успешное восстановление. Новые пути и профили через HTTP этой операции передать нельзя.
