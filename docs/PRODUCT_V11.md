# Следующий этап дорожной карты: восстановление review-сессии

Дизайн, шаблоны и содержание презентаций не менялись. Этот этап относится к локальному review worker, а не к облачному интерфейсу.

## Реализованный сценарий

Сотрудник оставляет замечание у слайда. Worker передаёт его Codex и сохраняет предложение через MCP. После штатной остановки worker запускается с прежними `--root`, `--codex-home`, `--model` и возобновляет сохранённый поток Codex. Если предложение уже записано, но ответ потерялся, worker добавляет ответ к существующему предложению без повторной генерации. Изменения документа по-прежнему принимает человек.

## Что добавлено

- Приватный `lanka-review.json` в отдельном Codex home: путь проекта, ID документа, модель, thread ID, число начатых inference-вызовов. Сам checkpoint не содержит токенов, ключей или текста презентации. История и файлы авторизации Codex могут находиться рядом; всю папку runtime нужно считать приватной.
- Явный `thread/resume` по схеме установленного Codex 0.153.4; при старте review `ephemeral=false`. Обычные задачи генерации сохранили прежнее ephemeral-поведение.
- Проверка принадлежности runtime до запуска Codex. Другой путь проекта, документ или модель отклоняются. Runtime нельзя размещать внутри общей папки презентации или использовать как её родительский каталог.
- Отдельная блокировка runtime и прежняя блокировка проекта: два worker не должны одновременно использовать одну историю.
- Лимит 20 inference-вызовов на сохранённую review-сессию. Попытка резервируется до отправки модели; перезапуск не сбрасывает счётчик. Восстановление ответа к уже созданному предложению не расходует inference.
- Ошибка восстановления останавливает worker; он не подменяет пропавший поток новой беседой незаметно для пользователя.

## Как продолжить сессию

Первый запуск требует пустой отдельной папки runtime. Дальше используется та же команда:

```sh
node runtime/project-review.mjs --root /ABS/PROJECT --codex-home /ABS/PRIVATE_RUNTIME --model YOUR_CONFIGURED_MODEL
```

Нужен установленный pinned runtime и `OPENAI_API_KEY` в окружении. Ключ не хранить в общей папке проекта. Завершение через Ctrl+C освобождает блокировки. После аварийного завершения процесса или машины блокировки могут остаться: оператор сначала проверяет отсутствие старого worker, затем удаляет только соответствующие `review-worker.lock` и `review-runtime.lock`. Автоматического захвата старой блокировки нет.

## Что проверено и что не доказано

Тесты используют настоящий локальный MCP/HTTP и файловое сохранение, но подставной ответ модели. Проверены перезапуск объекта worker с повторным открытием checkpoint, сохранение thread ID, восстановление после потерянного ответа на уже записанное предложение, отсутствие автоматического принятия, предел вызовов и изоляция runtime. Протокольный тест проверяет параметры `thread/start` и `thread/resume`.

Живой авторизованный Codex и восстановление его истории после перезапуска реального App Server ещё не проверены. Это отдельный обязательный прогон в среде клиента. При аварии между ответом модели и записью предложения inference может повториться; exactly-once генерация не обещается. Checkpoint не превращает облачную синхронизацию файлов в распределённую блокировку.

## Очерёдность следующих работ

| Приоритет | Работа | Критерий завершения |
| --- | --- | --- |
| 1 | Сквозной прогон с авторизованным Codex клиента | Замечание → предложение → остановка → восстановление того же thread → второе замечание → принятие |
| 2 | Организации, проекты и папки в облаке | Мои / общие документы, наследуемый доступ, отзыв доступа, изоляция двух организаций, включая агентные операции |
| 3 | Наблюдение за агентом и управление ошибками | В интерфейсе видны активная задача, ожидание пользователя, причина остановки и безопасный повтор |
| 4 | Источники и публикация | У утверждения есть основание; выпуск фиксирует данные, версию бренда, рендерер и согласование |

Brand Onboarding и визуальные эталоны остаются в дорожной карте, но работа над дизайном приостановлена по просьбе пользователя. Полный enterprise PRD этим этапом не закрыт.
