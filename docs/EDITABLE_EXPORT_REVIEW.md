# Проверка браузерного редактора и редактируемого PPTX

Дата: 6 сентября 2026. Это исследовательский проход для выбора архитектуры, а не приёмка корпоративного продукта.

## Вывод

Путь «браузер → редактируемый PPTX» работает для отдельных типов объектов. На одном и том же слайде два экспортёра дали разные результаты: CreatPPT сохранил диаграмму с данными, но нарушил вид; HTML-конвертер Presenton лучше сохранил композицию, но выгрузил столбцы отдельными фигурами. Для Lanka стоит развивать типизированные компоненты и общий RenderPlan. Автоматическое преобразование произвольного HTML не должно быть единственным способом экспорта данных.

## Что действительно запускалось

| Объект | Версия / источник | Граница проверки |
|---|---|---|
| CreatPPT | Установленный npm-пакет `@seekskyworld/creatppt@0.1.4`; отдельно прочитан репозиторий `8b7804b172d98e20c882a8d97c85b8a987d2b4dc` | CLI → локальный редактор → ручные клики → сохранение → перезагрузка → кнопка Export PPT в Chrome → файл |
| Presenton | Репозиторий `6bcd0bda4b5f38f39bb0c6ddc401a3ba9fb15473`, версия приложения `0.9.9-beta`; его штатный `@presenton/export-core@1.0.26`, редакция opensource | Конвертер `html-to-any` получил DOM/CSS уже отредактированного слайда CreatPPT. Собственный редактор Presenton, генерация моделью и его специализированные chart-компоненты в этом проходе НЕ запускались |
| Lanka | База `37a8815`, Focus 3 candidate | Прочитаны модель, сцена, canvas и экспортёр; пользовательские деки не изменялись |
| Slidev | [Официальная документация экспорта](https://sli.dev/guide/exporting.html#pptx) | Только документация: PPTX содержит изображения слайдов, текст не выделяется |

Архив конвертера получен штатным `scripts/sync-presentation-export.cjs` из официального релиза Presenton. SHA-256: `d792272cf2312a8e10d81143bfb406f9ee99689d5c546969e08bb2d31b5e98e5`. Его README прямо различает две редакции: opensource поддерживает только режим low quality. Проверка относится именно к нему; свойства другой редакции не предполагаются. Пакет содержит обфусцированный JS, типы и README; полного исходного кода конвертера в этом архиве нет. Условия повторного использования этого отдельного пакета ещё не проверены; зависимость в Lanka не добавлена.

## Контрольный сценарий

Один слайд Editorial с заголовком «Музейные коллекции», пояснением и диаграммой: Керамика — 20, Монеты — 30, Тексты — 40. Числа явно обозначены как условные. Это техническая фикстура, не историческая статистика. Изображение — bundled starter asset CreatPPT, использовано только для локального теста.

1. CLI создал `deck.json` без координат во входном задании. Три предупреждения о showcase/обложке ожидаемы для одностраничной chart-фикстуры; ошибок схемы нет.
2. В браузере заголовок изменён непосредственно на слайде на «Коллекции древнего мира», сохранён и проверен после перезагрузки.
3. На слайде число 20 изменено на 25. Save вернул 400: `chart.points.0.value` ожидает number, а получил string. После перезагрузки осталось 20. Неудачная правка не выдана за сохранённую.
4. Через Add Image добавлено изображение, затем в инспекторе заменено на `assets/editorial-library.jpg` и изменены размеры/положение. После Save и перезагрузки правки сохранились.
5. Нажата Export PPT в Chrome. UI сообщил о структурной проверке; скачанный файл сохранён как `creatppt-native.pptx`. Попытка скачивания во встроенном браузере не дала доступного файла; результат подтверждён именно в Chrome.
6. Из режима показа считаны DOM и CSS того же сохранённого слайда. Для Presenton добавлена штатная оболочка `presentation-slides-wrapper / main-slide / slide-export-inner`, размер 1280×720 и равномерный масштаб исходного слайда 1600×900. Изображение встроено как data URI. Тексты, значения и относительная композиция не переписывались. Первые ошибки отсутствующей оболочки/неразрешённого пути исправлены в адаптере фикстуры, они не считаются дефектами конвертера.
7. Полученный `presenton-html.pptx` и нативный файл разобраны как OOXML и отрендерены в PDF/PNG bundled LibreOffice. Просмотрены обе картинки и браузерный оригинал.

## Наблюдения

| Проверка | CreatPPT, штатный экспорт | Presenton, HTML этого слайда |
|---|---|---|
| Текстовые объекты с непустым текстом | 6 | 12, включая подписи/значения диаграммы |
| Изображения `p:pic` | 1 | 2: фотография и снимок всего слайда в нижнем слое |
| Нативная диаграмма `c:chart` | 1 | 0 |
| Встроенная таблица Excel | 1; B2:B4 = 20, 30, 40 | Нет |
| Заголовок одним текстовым блоком | Да | Да |
| Шрифт заголовка | Arial, хотя в браузере Georgia | Georgia |
| Столбцы при контрольном рендере | Скрыты белой подложкой | Видны как фигуры |
| Изображение | Отдельный объект, но кадр отличается от браузера | Отдельный объект, кадр ближе к браузеру |
| Полная приёмка | Не пройдена | Не пройдена: это тест конвертера, а не собственного редактора Presenton |

У CreatPPT диаграмма стоит в `spTree` раньше непрозрачного белого прямоугольника, который полностью её закрывает. Это соответствует [порядку в экспортёре](https://github.com/seekskyworld/CreatPPT/blob/8b7804b172d98e20c882a8d97c85b8a987d2b4dc/src/export/pptx.ts#L83): `addNativeChart` вызывается перед `renderElements`. Контрольный рендер LibreOffice показывает пустую белую область вместо графика. Сам файл при этом содержит корректные исходные значения и worksheet.

Причина ошибки числа также прослеживается: [сцена связывает подпись с числовым полем](https://github.com/seekskyworld/CreatPPT/blob/8b7804b172d98e20c882a8d97c85b8a987d2b4dc/src/domain/elements.ts#L176), а [редактор записывает `patch.text` по этому пути](https://github.com/seekskyworld/CreatPPT/blob/8b7804b172d98e20c882a8d97c85b8a987d2b4dc/src/editor/state.ts#L363). Типизированный редактор данных обязателен даже при удобном прямом редактировании текста.

Presenton действительно извлекает редактируемые текст и фигуры из HTML в проверенной редакции. Это сильнее, чем просто снимок. Но в наш входной HTML не передавались семантика диаграммы или специальная chart-разметка Presenton. Поэтому отсутствие native chart нельзя переносить на все способы экспорта Presenton. Это результат именно проверки универсального HTML-пути.

Визуальное сходство Presenton оценено по просмотренным изображениям; численный pixel-diff не заявляется. Текст, шрифты, crop и native chart нужно проверять в Microsoft PowerPoint отдельно. В этом проходе PowerPoint не открывался, а импорт в Keynote не удалось завершить через доступный UI; интерактивная правка Office-объектов и повторное сохранение остаются открытым критерием. OOXML подтверждает типы объектов и данные, но не качество работы конкретного клиента.

## Что это меняет для Lanka

- `lib/domain/scene.ts` уже даёт общий путь для браузера/PDF/PPTX, но сохраняет только rect/text/image. Семантика диаграммы теряется до экспортёра.
- `lib/export.ts` создаёт текстовые блоки по отрисованным строкам; большой абзац нельзя удобно редактировать как единый текст.
- `components/slide-canvas.tsx` привязывает клик к `editField`, но не поддерживает ввод прямо на слайде. Для непосредственной правки можно наложить HTML-поле на существующий SVG, сохранив проверенный рендер Focus 3.
- `Slide.chart` — массив без устойчивых ID строк/рядов, crop у изображения отсутствует, комментарии привязаны к слайду. Эти контракты нужно развить до сложной истории изменений и принятия отдельных блоков.
- Нативные объекты, правильные данные, воспроизводимый внешний вид и удобная дальнейшая правка — четыре отдельных критерия. Один счётчик `c:chart` не заменяет приёмку.

## Доказательства и повторение

Локальные материалы: `out/editable-export-review/` (игнорируется Git).

- `comparison.html` — автономное переключаемое сравнение трёх изображений с пояснениями.
- `creatppt-input.json`, `creatppt-workspace/deck.json`, `creatppt-after.json` — вход и сохранённое состояние.
- `creatppt-chart-save-failed.txt/.png` — браузерная ошибка числа.
- `creatppt-browser-slide.png`, `creatppt-dom.json`, `presenton-input.html` — оригинал и вход HTML-конвертера. На браузерном скриншоте также видны кнопки режима показа; они не входили в конвертируемый DOM слайда.
- `creatppt-native.pptx`, `presenton-html.pptx` — финальные сравниваемые файлы.
- `rendered/*.pdf`, `rendered/*.png` — контрольные рендеры; `ooxml-report.json` — объекты, порядок слоёв, шрифты, chart cache и worksheet.
- `presenton-run-final.log`, `presenton-final-receipt.json` — результат конвертера.

Для повторения UI-сценария использовать **новую** директорию фикстуры, не пользовательские документы. Исходный JSON сохранён в Git: `scripts/fixtures/editable-export/creatppt-input.json`. CLI: `node node_modules/@seekskyworld/creatppt/dist/node/cli.js create --from scripts/fixtures/editable-export/creatppt-input.json --out <new-workspace> --template editorial --json`, затем `serve <new-workspace> --host 127.0.0.1 --port <free-port>`. Проверить шаги 2–5 реальными кликами.

Повторный разбор файлов: `python3 scripts/inspect-pptx.py <file.pptx> [<second.pptx>]`. Использовать Python с исправным stdlib XML parser. В этой среде проверен bundled Python из `load_workspace_dependencies`; системный Homebrew Python имел ошибку загрузки expat.

Повторный экспорт подготовленной HTML-фикстуры: `node scripts/probe-presenton-export.mjs <installed-export-core/dist/index.js> <wrapped-slide.html> <output-directory> <chrome-executable>`. Инструмент не устанавливает пакеты и не меняет Lanka. Для контрольного PDF использовать только bundled LibreOffice; проверенный бинарник на этом Mac: `/Users/artemkruglov/.cache/codex-runtimes/codex-primary-runtime/dependencies/bin/override/soffice`.
