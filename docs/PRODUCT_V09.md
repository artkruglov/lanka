# Lanka v0.9 — шаблон и редактируемая ссылка

## Оценка прежнего дизайна

В v0.8 были контраст, единый шрифт и читаемые заголовки. Но тяжёлое начертание, повторяющиеся заполненные панели, декоративная буква на обложке и отвлечённый текст делали презентацию однообразной. Это авторская оценка конкретного файла; универсального стандарта «современности» нет.

Focus заменяет эти решения открытыми композициями, нормальным начертанием крупных заголовков, тонкими разделителями и более конкретным примером замечания. Палитра согласована с интерфейсом Lanka. Презентация всё ещё преимущественно текстовая: реальные скриншоты продукта не добавлены, поскольку браузерная проверка заблокирована средой. Пример работы агента подписан как пример, не как клиентский кейс.

Опираемся на [единый визуальный стиль](https://www.duarte.com/blog/perfect-your-slide-design/), [принципы иерархии и ясности](https://www.duarte.com/blog/4-presentation-design-principles-to-live-by/) и [контраст и чтение на небольшом экране](https://www.duarte.com/blog/design-slides-for-virtual-presentations/). Эти источники не подтверждают качество нашего конкретного шаблона: его оценивает человек по результату.

## Что теперь происходит с результатом агента

| Путь | Поведение | Ограничение |
|---|---|---|
| Облачный `create_deck` | Сохраняет документ, возвращает `links.editorUrl` и `links.presentationUrl` | Нужна авторизация этого облачного MCP |
| `get_deck_links` | Возвращает постоянные ссылки после проверки доступа | Ссылка не является приглашением или токеном доступа |
| `/presentations/:id` | Открывает конкретный документ и сохраняет путь при входе | Для просмотра нужны доступ к сервису и роль на документе |
| Режим показа | Та же ссылка с `mode=present` открывает показ | Сохранённая рабочая версия; не заменяет immutable release |
| Пример `/examples/lanka-sales` | При первом открытии сохраняет личную копию; при повторном возвращает её с правками | Для совместной работы передавать ссылку на документ, а не ссылку на пример |
| Локальный `export_handoff` | Создаёт JSON документа с проверенными байтами материалов | Файл до 450 КБ; загрузка в облако — явный импорт человеком |
| Импорт JSON в редакторе | Создаёт новый документ, переносит материалы в R2, сохраняет метаданные в D1 и переназначает ID | Не импортирует ACL, approvals, историю чужих сессий; не синхронизирует папку с облаком |

В интерфейсе ссылка доступна в верхней панели, в «Поделиться» и в «Ссылка и файлы». Облачный MCP передаёт её агенту без дополнительного шага. Локальному MCP запрещено придумывать облачный URL для ещё не загруженного проекта: он честно возвращает `upload_required`.

## Структура дизайна

Полный контракт находится в `design-packs/focus-v1/README.md`. Токены, рецепты и fixtures отделены от сценария сейлз-презентации. Общий рендерер использует токены, а агент читает ограничения через `get_authoring_guide`. Проверка дизайна входит в `lint_deck`; она выдаёт предупреждения, а не сертификат красоты.

Существующие версии дизайна сохранены. Новые документы используют Focus. Геометрия опубликованного Focus v1 закрепляется; её изменение потребует новой версии. Содержание и источники хранятся в DeckDoc и проекте независимо от оформления.

## Проверка

Сейлз-презентация пересобрана настоящими stdio MCP-вызовами: создание рабочего документа → предложение изменений всех слайдов → применение явно запрошенной пользователем правки через тот же сервис мутаций, который использует редактор → lint → PPTX/PDF и handoff. Результат не создан обходным отдельным генератором презентаций.

Интеграционные проверки покрывают постоянные ссылки, повторное открытие с сохранённым заголовком, изоляцию владельцев, запрет чтения чужих материалов, перенос байтов и защиту от устаревшей версии. Геометрические fixtures покрывают все 10 композиций, русский и английский текст, отрицательные и нулевые значения графика и отказ при переполнении.

Облачный браузер отклонил внутренний адрес предпросмотра по своей URL-политике. Поэтому клики, мобильная верстка и вход по реальному аккаунту в этой итерации не проверены. Ограничение не обходилось. PDF проверяется отдельно по каждому слайду. Ранее созданный Codex runtime не стал авторизованным от этих изменений.

## Следующие обязательные работы по PRD

1. Поддерживаемый авторизованный cloud MCP и реальный прогон с агентом клиента: краткий запрос → вопросы → план → слайды → ссылка → замечание → правка.
2. Browser/mobile acceptance на доступном стенде: открыть ссылку после входа, изменить и перезагрузить, одновременно открыть коллегой; проверить отказ после отзыва доступа.
3. Brand Onboarding: материалы бренда → предложение токенов и рецептов агентом → набор реальных визуальных эталонов → утверждение дизайнером → версия Brand Pack. Сейчас реализована структура и один кандидат, не весь мастер.
4. Организации, папки, наследование прав, SSO и изоляция runtime каждого клиента. Текущая роль на документе не заменяет эту модель.
5. Возобновляемые сессии и очередь, события вместо polling, голосовые заметки с подтверждением текста, semantic rebase и lineage публикации.

v0.9 закрывает конкретный разрыв доставки и повторного использования дизайна. Она не означает завершение всех требований enterprise PRD.
