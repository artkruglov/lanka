# Запуск личного чата Lanka

Это локальный однопользовательский режим. Сервер слушает только `127.0.0.1`; PostgreSQL принимает соединения через приватный UNIX socket текущего пользователя. Это не готовая многопользовательская установка компании.

Нужны Node ≥22.13, npm, PostgreSQL 16+ с `pg_ctl`, установленный официальный Codex CLI. Проверенный CLI: 0.153.4. На Mac скрипт также находит PostgreSQL 16 в стандартной папке Homebrew. Бинарники и доступ к провайдеру устанавливаются/настраиваются отдельно.

Из корня репозитория:

```bash
npm ci
npm run setup:chat
npm run restart:local
```

Последняя команда использует macOS launchd. Для запуска в терминале на системе с UNIX sockets: `npm run start:local`. Открыть `http://127.0.0.1:4317/`, создать документ и нажать «Обсудить». В старом документе выбрать «Создать копию для чата». Новая установка использует отдельный профиль Codex для Lanka: нажмите «Войти в Codex», завершите вход по коду в своём аккаунте, затем подключите агента. Незавершённый вход после перезапуска нужно начать заново. Существующие установки сохраняют настроенный профиль до явного переключения ниже.

`setup:chat` создаёт собственный кластер и БД `lanka_chat` в `work/agent-chat`, конфигурацию с правами 0600 и socket/runtime dirs с правами 0700. Не изменяет существующие базы PostgreSQL и не открывает его TCP-порт. Файл конфигурации привязан к абсолютному пути `work/local-library`: другая библиотека/тестовый корень не подключаются автоматически. После перемещения проекта эту привязку и пути socket/runtime нужно обновить осознанно; повторный setup не перезаписывает конфигурацию.

Настройки включают путь к установленному CLI и локальному профилю авторизации. В отдельном режиме CLI хранит авторизацию и native-сессии под `runtimeRoot/codex-profiles/<tenant>/<owner>` с правами 0700. Секреты и настройки прежнего профиля не копируются; секреты не попадают в HTML или логи. Сам CLI управляет входом. Настройки провайдера для нового профиля при необходимости задаются отдельно. Выбранный провайдер может быть внешним: локальное приложение не превращает облачную модель во внутреннюю модель компании.

Новые документы, история, материалы, предложения и беседы находятся в PostgreSQL. Старая файловая библиотека остаётся доступной. Внешний stdio MCP поддерживает оба хранилища; получите конфигурацию конкретного документа в панели агента, в разделе «О сессии и подключении через MCP». [Общий MCP и его ограничения](planning/SHARED_MCP_ACCEPTANCE.md).

Локальные ограничения: один исполнитель одновременно; 20 запусков в сутки UTC на владельца, до 100 поручений в беседе, до пяти ожидающих, до четырёх минут на job. UI пока отправляет следующий запрос после завершения/отмены текущего. Лимит запусков не является финансовой квотой провайдера. «Остановить» запрещает дальнейшие записи сразу; подтверждение interrupt хранится отдельно.

Обычный перезапуск повторно поднимает настроенный PostgreSQL и не пересоздаёт данные. На Mac `start:local:background`/`restart:local` устанавливают собственный LaunchAgent `~/Library/LaunchAgents/local.lanka-studio.web.plist`: он запускает Lanka при входе пользователя и перезапускает завершившийся веб-процесс. Стартовый wrapper сначала поднимает приватное хранилище. `npm run stop:local` останавливает веб-сервис и убирает его автозапуск, сохраняя документы; приватный PostgreSQL может продолжать работать. Backup/restore, upgrade, OIDC и полная серверная эксплуатация входят в следующий self-hosted этап. Не удаляйте `work/agent-chat`: там находятся новые пользовательские документы и беседы.

Для проверки без генерации: `npm run test:chat` создаёт собственные случайные test tenants и удаляет только их после проверки. Для явной платной/квотируемой проверки исполнителя см. [приёмку](planning/CHAT_ACCEPTANCE.md). [Решение о готовых компонентах и архитектуре](planning/CHAT_IMPLEMENTATION.md) содержит дальнейший план.

## Если беседа занята другим Codex

При повторных блокировках откройте «О сессии и подключении через MCP» → «Отдельное подключение для Lanka» → «Перейти к отдельному входу». Переключение касается всех ваших презентаций этой установки и разрешено только при отсутствии незавершённых поручений. Документы и переписка сохраняются; новые native-сессии восстановят контекст из Lanka. Войдите в свой аккаунт для нового профиля и подключите агента. [Проверка миграции и границы живой приёмки](planning/DEDICATED_CHAT_ACCEPTANCE.md).

Lanka показывает конкретный отказ и предлагает «Продолжить в новом контексте». После объяснения и подтверждения история Lanka остаётся на месте; следующий запрос запускает новый контекст вашего Codex, который может прочитать прежнюю переписку через ограниченный MCP. Старый клиент не останавливается, его новые сообщения сюда не переносятся. Если вы хотите сохранить именно прежний native-контекст, освободите его в другом клиенте и повторите отправку без восстановления. [Проверенный сценарий и границы](planning/CHAT_CONTEXT_RECOVERY_ACCEPTANCE.md).
