# Выполнение чертежа v3 — этап 0.4

Дата: 5 сентября 2026. Это отчёт о реализованном коде и проверках, а не объявление всего PRD готовым. Исходный план: [PRODUCT_BLUEPRINT_V3.md](PRODUCT_BLUEPRINT_V3.md).

## Что теперь можно сделать

Главная страница — задачи. Пользователь сохраняет бриф, выбирает встроенный стиль и число слайдов, прикладывает материалы и запускает подготовку. Задача хранит вопросы/ответы, извлечённые фрагменты, предлагаемый план, кандидат презентации, замечания и события. Предусмотрены два человеческих решения: принять логику, затем принять все новые слайды. Готовая презентация открывается в существующем пространстве обсуждения, предложений, согласования и экспорта.

Canvas остаётся read-only. Последующая точная корректировка по-прежнему выполняется через отдельный диалог и предложение с просмотром до/после. Первичная генерация принимает всю новую деку; это ещё не универсальные структурные change groups для вставки, удаления и перемещения слайдов существующего документа.

Без подключённого worker задача честно остаётся в очереди. Демо-ответы и сгенерированные вручную планы не выдаются за работу модели.

## Проверки и границы доказательств

Доменный набор проверяет реальную сгенерированную SQL-схему, атомарность, гонки исполнителей, ответы/продолжение, отмену, истечение lease, отзыв доступа, принятый план, кандидат и конфликт с человеческой ревизией. Протокольные и worker-тесты используют подставленные ответы; тесты извлечения используют локальные Office-фикстуры. Полные результаты: [VALIDATION.md](VALIDATION.md).

Установленный Codex ранее успешно ответил на initialize/account-read; аккаунт, выбранная модель и gateway не были настроены. Это подтверждает запуск протокола, а не создание презентации. Финальная конфигурация контейнера и выполнение с моделью не проверены. Браузерная визуальная проверка, внешнее облачное размещение и приёмка качества шаблонов также не выполнялись.

## Следующий сквозной запуск

1. Указать существующий репозиторий/конфигурацию внешнего окружения `shop reuse app` в `hills` либо подготовить отдельное окружение worker. В доступной рабочей папке эти настройки не найдены; новое облако не создавалось.
2. Настроить gateway с авторизованной делегацией и отдельными полномочиями агента. Секреты задать через менеджер секретов, не через чат.
3. Запустить worker по [runtime/README.md](../runtime/README.md), выбрать доступную аккаунту модель и выполнить реальный цикл с тремя файлами.
4. Проверить вопросы, принятие плана, аргументацию, отсутствие неподтверждённых чисел, отмену и повтор. После этого закрывать Codex gate.
5. Продолжить Brand Onboarding и серверный выпуск: эти требования исходного PRD остаются обязательными для корпоративного пилота.
