# Handoff: Focus 3 («редакционный») для Lanka Studio

Пакет для внедрения нового базового шаблона `focus-v3` в рабочий проект `/workspace/sites/lanka-studio`
(снимок `fe8810d80fea8b866e75006376141c5350ecc431`). Собран 5 сентября 2026 по итогам независимого разбора
(`../FABLE_REVIEW.md`) и визуального концепта (канвас «Lanka Base»).

Что здесь уже сделано и проверено локально, без доступа к репозиторию Lanka:

- Рендерер `lib/domain/focus-v3.ts` написан против существующих типов `Slide`, `Brand`, `Primitive`, `Scene`
  и прогнан на 11 фикстурах и на примере деки из 9 слайдов (`scripts/render-fixtures.ts`, bun).
  Ноль переполнений после калибровки. PNG каждого слайда лежат в `design-packs/focus-v3/golden-candidate/`.
- Метрики шрифта IBM Plex Sans (Regular, SemiBold) и IBM Plex Mono (Medium) сгенерированы из TTF
  (`lib/domain/font-metrics-plex.json`), сами файлы и лицензии OFL лежат в `fonts/`.
- Эталоны концепта (то, как это должно выглядеть) лежат в `design-packs/focus-v3/reference/`.

Что здесь нельзя было сделать и что делает агент или разработчик в репозитории: патчи в существующие файлы
(`PATCHES.md`), поддержка `font` и `tracking` в экспортерах SVG/PDF/PPTX, маршрут примера, тесты, golden-diff.
Готовое задание для агента в рабочей среде: `CODEX_TASK.md`.

## 2. Что такое Focus 3 в трёх абзацах

Сетка: холст 1600 × 900, поле 96, 12 колонок по 88 с межколонником 32, шаг 8. Всё, что рисует рендерер,
берёт координаты из `col(i, span)`; ручных `y` нет. Заголовок стоит на `zones.titleTop = 168`,
блок доказательства прижат к `zones.contentBottom = 796`, между ними воздух. Обложка устроена иначе:
заголовок прижат к подводке снизу, как плакат.

Типографика: IBM Plex Sans 400 и 600 для текста, IBM Plex Mono 500 для служебных подписей в капителях
с трекингом 12 %. Роли и кегли перечислены в `tokens.json → typography.roles`. Заголовки h1 сначала
пробуют 10 колонок, при переполнении или заполнении строки больше 90 % расширяются до 12; строки
балансируются, как `text-wrap: balance`. Предлоги приклеены к следующему слову, тире к предыдущему.

Цвет и ритм: бумага `#F6F6F3`, чернила `#15182A`, синий Lanka `#444BE8` без изменений, `brand.accent`
`#A9AEFF` работает второй строкой на тёмном тезисе. Синий как поверхность только на финале; светлая
tint-карточка единственная вторичная поверхность; синий текст не больше одного класса элементов на слайд.
Линейка справа вверху показывает место слайда в деке. Три удара на деку: бумага открывает, тёмный тезис
после доказательства, синий закрывает.

## 3. Порядок внедрения

1. Скопировать новые файлы в репозиторий по тем же путям: `design-packs/focus-v3/`, `lib/domain/focus-v3.ts`,
   `lib/domain/scene-text-v3.ts`, `lib/domain/font-metrics-plex.json`, `lib/examples/lanka-sales-focus-v3.json`,
   `fonts/` (или тот каталог, откуда экспортеры уже берут DejaVu), `scripts/`.
2. Применить `PATCHES.md`: `scene.ts` (тип примитива и диспетчер), `design.ts` (новый ID), `model.ts`
   (`comparison`, `columnRoles`, lint), `design-review.ts` (метрики раскладки), `authoring.ts` (контракт v3).
3. Экспортеры SVG, PDF, PPTX: научить выбирать семейство по `font`, применять `tracking`, встраивать три TTF,
   класть базовую линию по формуле из `scene-text-v3.baseline()`. Подробности в `PATCHES.md → Экспортеры`.
4. Прогнать `bun scripts/render-fixtures.ts` внутри репозитория (после патчей он должен работать без изменений),
   затем реальный экспорт фикстур в SVG/PDF/PPTX и сравнить с `golden-candidate/`.
5. Добавить маршрут `/examples/lanka-sales-focus-v3` по образцу v2: первое открытие создаёт личную копию.
6. Не менять `defaultDesign`, не трогать `focus-v1`, `focus-v2` и их примеры. Переключение дефолта и смена
   бренда у существующих документов происходят только явным действием после приёмки.

## 4. Шрифт: решение и риски

Выбор: IBM Plex Sans + IBM Plex Mono, лицензия SIL OFL 1.1 (файлы лицензий в `fonts/`). Причины: качественная
кириллица, одна семья для текста и служебных подписей, не заезженный в SaaS-деках, доступен на Google Fonts
для веб-редактора. Консервативная альтернатива с той же механикой: Golos Text + JetBrains Mono.

Метрики регенерируются командой:

```bash
python3 scripts/font-metrics.py fonts/IBMPlexSans-Regular.ttf fonts/IBMPlexSans-SemiBold.ttf fonts/IBMPlexMono-Medium.ttf > lib/domain/font-metrics-plex.json
```

Риски:
- PDF: pdf-lib с fontkit встраивает TTF; трекинг нужно задавать оператором character spacing или рисовать
  по глифам. Кернинг рендерер не учитывает, поэтому измерения на 1–3 % консервативнее реального набора.
- PPTX: без установленного шрифта PowerPoint подставит другой, и переносы поплывут. Варианты: встроить шрифты
  в пакет (`embeddedFontLst`, работает в Windows PowerPoint, игнорируется Keynote и Google Slides), либо
  документировать PDF как канонический экспорт, а PPTX как редактируемую копию.
- Веб-редактор: подключить те же TTF через `@font-face` из статики проекта, не через внешний CDN.

## 5. Проверка

Механика (есть в проекте): переполнение, контраст, бюджеты слов, число частей.

Метрики раскладки (новые, считает `focusV3Scene(...).meta`):

| Метрика | Порог из `tokens.policy` | Что ловит |
| --- | --- | --- |
| `titleLines` | display ≤ 3, h1 ≤ 2 | заголовок нужно сократить |
| `titleFill` | ≤ 0.90 | строка упирается в поле |
| `occupancy` | 0.12 … 0.42 | пустой или перегруженный слайд |
| `contentHeight` | ≥ 150 для слайдов с доказательством | доказательство превратилось в сноску |
| `gap` | ≥ 64 | заголовок наехал на контент (ставит overflow) |
| `primaryTextClasses` | ≤ 1 | синий расползся |
| соседство | одинаковый layout ≤ 2 подряд; split не рядом со split; statement один и после первого доказательства | ритм деки |

Фактические значения на примере деки после калибровки лежат в выводе `render-fixtures.ts` и в
`CODEX_TASK.md → критерии приёмки`.

Человеческая приёмка (владелец деки, затем бренд-дизайнер):
1. Можно ли назвать главное на каждом слайде за три секунды?
2. Есть ли ритм, если смотреть миниатюры всей деки в ряд?
3. Только ли финал и тезис насыщенные?
4. Есть ли слайд, похожий на недоделанную страницу?

## 6. Открытые решения владельца

- Когда переключать `defaultDesign` на `focus-v3` (после golden-diff и приёмки бренд-дизайнером).
- Менять ли `brand.paper` у существующих документов при смене дизайна (по умолчанию нет; новый бренд
  `lanka-default` версии 2 лежит в примере деки).
- Стратегия PPTX: встраивание шрифтов или «PDF канонический».
- Конвенция мета-строки обложки: второй абзац `body` показывается в футере моноширинным.

## 7. Что не проверено

- Компиляция `focus-v3.ts` с реальными `model.ts` и `scene.ts` проекта: типы взяты из выдержек, а не из репозитория.
- Экспортеры: их код в пакет для ревью не входил. Требования описаны, объём правок не оценён.
- Рендер PPTX в PowerPoint, Keynote и Google Slides.
- Пороги метрик откалиброваны на одной деке и 11 фикстурах.
