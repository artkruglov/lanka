# Focus 2 — ясный акцент

Простой корпоративный шаблон Lanka с белым фоном, тёмным текстом и синим акцентом. Продолжает Focus 1, но делает иерархию и разницу между задачами слайдов заметнее. Статус — кандидат; корпоративную сертификацию должен выполнить бренд-дизайнер клиента.

## Что исправлено после визуального разбора

В Focus 1 крупный обычный заголовок, длинная поясняющая строка и тонкая линия часто давали одинаковую композицию. На слайде с замечанием было описание работы агента, но не было самого исходного заголовка. Две таблицы подряд повторяли силуэт. Синяя черта на обложке мало помогала понять и запомнить продукт.

В Focus 2 у синего есть функции: поле обложки, шапка таблицы, следующий шаг. Полужирные заголовки отделены от обычного текста. Сравнение показывает две подписи и крупные примеры; процесс читается сверху вниз. Служебная строка собрана в один компактный верхний ряд. Поля и палитра остаются узнаваемыми.

## Файлы контракта

| Файл | Назначение |
| --- | --- |
| `tokens.json` | Типографика, цвета, холст, интервалы и политика изображений |
| `recipes.json` | Задача каждой композиции, структура текста и бюджет |
| `fixtures.json` | Девять содержательных примеров без фиктивного изображения |
| `../../lib/domain/focus-v2.ts` | Геометрия для единой сцены SVG, PDF и PPTX |
| `../../lib/domain/authoring.ts` | Контракт, доступный агентам через MCP, включая закреплённый v1 |
| `../../examples/sales-focus-v2.ts` | Воспроизводимое редактирование сейлз-деки через локальный MCP |
| `../../lib/examples/lanka-sales-focus-v2.json` | Содержание примера, отдельно от шаблона |

Все размеры — единицы холста 1600 × 900. Текст не уменьшается автоматически. Переполнение требует сокращения содержания или другой композиции. Заголовок обычного слайда — до двух строк; узкий заголовок `content`/`steps` допускает больше строк по высоте рамки. Обложка, ключевой вывод и финал — до трёх строк.

## Изображения

По умолчанию их нет. Генерация иллюстраций запрещена инструкцией шаблона. Разрешён реальный материал клиента, если он помогает доказать тезис: скриншот, фотография, документ. Композиция `image` сохранена для таких материалов. Фиктивных скриншотов, стоковых украшений и неподписанных условных графиков быть не должно.

Это контракт для агента и проверяющего человека. Текущая модель ассетов проверяет байты и принадлежность проекту, но не умеет доказать происхождение изображения или определить, было ли оно сгенерировано. Не считать инструкцию техническим детектором.

## Как повторить качество

1. Сначала собрать бриф и один вывод для каждого слайда; неизвестное пометить допущением.
2. Выбирать композицию по задаче, а не циклически. Для сравнения: первая строка каждого блока — подпись, следующие — сам пример.
3. Показывать изменение, данные или конкретный сценарий. Не придумывать цифры ради графика.
4. Убрать подробности в заметки, выполнить lint, экспортировать и визуально проверить каждый слайд.
5. Дать пользователю ссылку на сохранённый документ. Проверка дизайна не заменяет проверку фактов и прав доступа.

## Версионирование

`focus-v1` и старый сейлз-пример сохранены. Новый пример открывается по `/examples/lanka-sales-focus-v2`, создаёт отдельную личную копию при первом открытии и затем возвращает её с сохранёнными правками. Это важно: обновление демонстрации не должно перезаписывать рабочую презентацию пользователя. Новые документы по умолчанию используют `focus-v2`; существующие меняют дизайн только явным действием.

После публикации геометрию v2 нельзя менять незаметно для существующих документов. Следующее изменение композиционной системы должно получить новый ID. Полные эталонные изображения, подтверждение корпоративного бренда и проверка экспорта в целевом Office остаются отдельной работой.
