# Focus v1

Переиспользуемая дизайн-система Lanka для корпоративной продуктовой презентации. Статус: кандидат, проверенный на тестовых композициях и сейлз-примере. Это не сертификация бренда клиента.

## Контракт

- `tokens.json` — холст, поля, шкала типографики, палитра, интервалы и правила плотности. Размеры в единицах холста 1600 × 900; не в пунктах PowerPoint.
- `recipes.json` — назначение каждой композиции, бюджет текста, ограничения. Это инструкции выбора для агента; рендерер реализует геометрию.
- `fixtures.json` — короткие русские и английские примеры, таблица, отрицательные и нулевые значения графика, слот изображения.
- `../../lib/domain/focus.ts` — единая реализация сцены для SVG, PDF, PPTX. Использует токены. Материалы подключаются по ID, исполняемый код в документ не попадает.
- `../../lib/domain/design-review.ts` — предупреждения о плотности, контрасте и трёх одинаковых композициях подряд.
- `../../lib/examples/lanka-sales.json` — отдельное содержание демонстрации, созданное и отредактированное через MCP. Не является шаблоном, из него нельзя наследовать продуктовые утверждения для другого клиента.

## Визуальные правила

1. Один вывод на слайд, конкретный заголовок. До двух строк, на обложке и ключевом выводе — до трёх.
2. Светлый холст, тёмный текст, индиго для смыслового акцента. Тёмная композиция — для ключевого вывода. Другой клиент задаёт свои проверенные Brand-цвета.
3. Обычное начертание у крупных заголовков; полужирное — у коротких подзаголовков. Не заполнять слайд декоративной буквой или набором карточек.
4. Сокращать текст до снижения размера. Рендерер сообщает о переполнении и не уменьшает шрифт автоматически.
5. Использовать изображение, таблицу или график, когда они несут доказательство. Скриншот должен быть реальным; пример или макет нужно подписывать. Не выдумывать метрики для разнообразия.
6. Ссылки и названия источников — в заметках и панели материалов. Повторяющиеся «Материалы [1]» без идентификации источника не создают прослеживаемости.

## Приёмка и версионирование

Запустить доменные тесты; экспортировать все fixtures; визуально проверить каждый итоговый слайд и весь ритм деки. Изображение fixture проверяет только рамку; перед сертификацией нужны реальные фотографии и скриншоты. Проверить длинный русский текст, контраст выбранного бренда и открытие PPTX в целевом Office. Полный набор golden-изображений с утверждением бренд-дизайнера ещё предстоит собрать.

Выпущенный `focus-v1` нельзя менять так, чтобы старые документы внезапно перерисовались. Для изменения геометрии выпускается `focus-v2`, пользователь явно переводит документ. Версия дизайна уже записана в DeckDoc; серверные revisions сохраняют документ целиком.

## Основания оценки

Общего стандарта «современной красивой презентации» нет. Проверяем понятность, визуальную иерархию, единство стиля, соответствие аудитории и удобство чтения. См. [Duarte: единство стиля и дизайн](https://www.duarte.com/blog/perfect-your-slide-design/), [Duarte: четыре принципа](https://www.duarte.com/blog/4-presentation-design-principles-to-live-by/), [Duarte: экран и контраст](https://www.duarte.com/blog/design-slides-for-virtual-presentations/). Эти рекомендации не сертифицируют наш шаблон и не доказывают его превосходство над другими продуктами.
