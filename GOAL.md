**Текущий срез, 7 сентября:** [поручение из UI выполняется пользовательским Codex через MCP](docs/planning/NATIVE_UI_CHAT_ACCEPTANCE.md). Рабочая цель уточнена; внешний двусторонний bridge остаётся следующим этапом.

**Новое уточнение цели:** [презентации за минуты и простая работа агентов](docs/planning/SIMPLE_PRODUCT_GOAL.md). Сценарии 15/5 минут — измеряемые цели, не достигнутые показатели; разработка продолжается.

**Текущая цель с 6 сентября 2026:** [сценарии большой компании → разработка → проверенная открытая поставка](docs/planning/GOAL_TRACKER.md). Нижеследующий текст сохранён как исторический срез [v0.8](docs/PRODUCT_V08.md).

## Результат для организации

Дать командам единое пространство для создания, редактирования, обмена и выпуска корпоративных презентаций. Основной способ работы — задачи готовому агентному runtime: Codex внутри сервиса, затем другие совместимые агенты. Пользователь работает в нашем интерфейсе; собственный цикл одного запроса к LLM не является целевым продуктом. Бренд, данные, доступ, история, согласование и выпуски принадлежат сервису и сохраняются при смене модели.

## Измеримый пилот

Одна команда и один повторяющийся отчёт: импорт структуры → презентация в шаблоне → предложение агента → ручная корректировка → комментарии → утверждение точной версии → выпуск PDF/PPTX → обновление следующего периода.

Провести 10 реальных циклов, измерить время активной ручной работы против исходного процесса. Цель: медианное снижение минимум 30%, отсутствие потерянных ручных правок, прослеживаемость всех принятых изменений, 100% выпусков привязаны к утверждённой ревизии. Это целевые, пока не измеренные значения.

## Исторические приоритеты 0.3 (уточнены ниже в 0.5)

Полный аудит, сценарии и план размещения: [docs/IMPLEMENTATION_GAP_REVIEW.md](docs/IMPLEMENTATION_GAP_REVIEW.md). Матрица требований: [docs/REQUIREMENTS_MATRIX.md](docs/REQUIREMENTS_MATRIX.md).

Текущая 0.3 — прототип review-first workspace с брифом, картой логики, ревизиями и контролем изменений. Подробный чертёж: [PRODUCT_BLUEPRINT_V3.md](docs/PRODUCT_BLUEPRINT_V3.md). Inline-редактирование исключено по уточнению заказчика. Обязательная демонстрация PRD v2 §1.5 ещё не реализована. 38 автоматизированных тестов подтверждают отдельные механизмы; это не приёмка всего P0.

1. **Первый замкнутый сценарий.** Бриф + три файла + корпоративный шаблон → Codex в изолированном worker → уточняющие вопросы → 10 слайдов и источники → render/lint/repair → proposal с preview → четыре комментария → delta-proposal → частичное принятие → разные Reviewer/Publisher → PDF и manifest. Повторить через внешний MCP/CLI на тех же доменных объектах.
2. **Исполнение и инфраструктура.** Отдельный Codex runtime с адаптером App Server, рабочим каталогом и версионированными навыками. Устойчивая очередь, события, вопросы/ответы, lease/fencing, возобновление без слепого повтора побочных действий. Node API, PostgreSQL, S3 и изолированные workers; конкретный внешний проект выбирается после получения сведений о `shop reels.app` в `higgsfield`.
3. **Основной интерфейс.** Создание из брифа — главное действие; workspace показывает активные задачи и ожидающие решения. Отдельный экран выполнения: план, вопросы, источники, промежуточные слайды и отмена. Review показывает визуальное сравнение, категории изменений и связанные комментарии; точная корректировка выполняется отдельной формой и проходит через proposal, canvas остаётся read-only.
4. **Ядро P0.** Стабильные блоки, candidate revision, typed commands, зависимости change groups, контролируемый checkout и единый Tool Service. Tenant/workspace/OIDC, отдельная agent identity и scopes, запрет human endpoints для агента.
5. **Brand Onboarding — P0.** Извлечение брендбука/PPTX/POTX/референсов; authority, evidence, конфликты, coverage, recipes, fixtures, тестовая дека и только человеческая сертификация BrandPackRelease. В первом внедрении ведут интегратор и дизайнер; полный self-service позже.
6. **Визуалы, источники и выпуск — P0.** Извлечение Office/PDF/XLSX с якорями и отчётом; snapshots/единицы/даты; библиотека ассетов; image broker и provenance; серверный авторитетный render/PDF; immutable artifact и полный manifest; eval corpus и приёмка на реальной команде.
7. **После P0.** Presence/realtime по доказанной потребности, расширенный PPTX round-trip, расписания регулярных отчётов, развитый каталог переиспользования и массовые обновления. Существующий PPTX экспорт сохраняем как адаптер, но не расширяем раньше замыкания основного сценария.

## Definition of Done для enterprise-релиза

- Границы арендаторов и полномочия проверены серверными интеграционными тестами.
- Отмена, повторная отправка команды и падение провайдера не создают лишних/несогласованных изменений.
- Каждый выпуск закрепляет документ, бренд, данные, изображения и версию рендера; можно воспроизвести экспорт.
- Корпоративный template intake прошёл реальные fixtures и человеческую сертификацию.
- Проведены нагрузочная проверка, доступность, совместимость Office, восстановление из backup.
- Выполнены критерии пилота; пользовательские данные и лицензии отвечают выбранной политике размещения.

## Актуальное уточнение: 0.5

Последнее решение заказчика возвращает прямое ручное редактирование: выбрать слайд → изменить поля справа → увидеть результат → сохранить. Реализованы текст, данные, композиция, источники/изображение и заметки; autosave с проверкой ревизии, undo/redo и сохранение локального ввода при запаздывающем ответе. Агент слева; его изменения по-прежнему проходят review. Это заменяет прежнее ограничение «любая ручная правка только через proposal».

В библиотеке есть «Мои» / «Открыли мне доступ», явные участники и внутренняя ссылка. Это ещё не Tenant/Workspace/приглашения и не общий realtime. Настройки Cloudflare/Fly и отдельный внешний auth entry point подготовлены; реальные аккаунты Higgsfield, внешний worker и модель не подключены. Neon требует миграции D1, а не переменной окружения.

Полный текущий чертёж, матрица PRD, план левого чата с Codex, browser/voice feedback и качества шаблонов: [PRODUCT_WORKSPACE_V4.md](docs/PRODUCT_WORKSPACE_V4.md). Сверка восьми OSS-проектов: [EDITOR_REUSE_REVIEW_V05.md](docs/EDITOR_REUSE_REVIEW_V05.md). Руководство по размещению: [deploy/README.md](deploy/README.md).

Следующая приёмка — живой Codex-сценарий на реальном внешнем окружении, затем команда/доступ, постоянный чат и комментарии, авторитетный render и настоящий BrandPack. Выполненные локальные тесты подтверждают механизмы, а не качество генерации или готовность enterprise-релиза.

## Последнее решение: 0.6 — клиент контролирует проект

Общая база содержимого многих организаций больше не является целевой отправной точкой. Основной сценарий — папка клиента, выбранный проект и индивидуальное подключение исполнителя. Реализованы переносимый ZIP из интерфейса и локальный MCP для одной папки; через него создана демонстрационная презентация. Веб-редактор пока использует D1/R2, интеграция с корпоративным файловым хранилищем и живой Codex требуют продолжения.

Актуальные бизнес-требования и следующий этап: [CLIENT_PROJECTS_V06.md](docs/CLIENT_PROJECTS_V06.md).
